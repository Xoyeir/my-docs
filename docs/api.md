# API 参考

以下接口仅用于文档展示，不提供真实服务。

本页的目的是练习接口文档的写法：把请求方法、路径、参数和返回示例放在一起，让读者不必追问也能正确调用。

## 查询文档列表

- 请求方法：GET
- 请求路径：/api/docs
- 功能：返回文档条目列表。

### 请求参数

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| page | 整数 | 否 | 页码，从 1 开始，默认 1 |
| size | 整数 | 否 | 每页条数，默认 20，最大 100 |

### 返回示例

```json
{
  "items": [
    {"id": 1, "title": "使用指南"}
  ],
  "total": 1,
  "page": 1
}
```

### 返回字段说明

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| items | 数组 | 当前页的文档条目 |
| items[].id | 整数 | 文档编号 |
| items[].title | 字符串 | 文档标题 |
| total | 整数 | 文档总数 |
| page | 整数 | 当前页码 |

## 获取单篇文档

- 请求方法：GET
- 请求路径：/api/docs/{id}
- 功能：按编号返回一篇文档的详细内容。

路径中的 `{id}` 需要替换为实际编号，例如 `/api/docs/1`。

### 返回示例

```json
{
  "id": 1,
  "title": "使用指南",
  "content": "本页说明文档站点的日常维护流程。"
}
```

## 我的理解

写这一页时我意识到，接口文档和普通说明文档的差别在于“可核对”：参数名、类型、是否必填、返回结构都必须和实现一致，读者会照着文档直接发请求。因此在真实项目中，接口一旦变更，文档必须同步修改，否则比没有文档更糟。本页的示例虽然不连接真实后端，但保留了同样的结构，便于以后替换为真实接口。
