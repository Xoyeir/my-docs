# 使用指南

本页说明文档站点的日常维护流程，适用于仓库和 MkDocs 配置已经完成之后的使用阶段。

## 发布流程

1. 修改 docs 目录中的 Markdown 文件。
2. 在本地预览并检查页面及链接。
3. 提交修改并推送到 main 分支。
4. 在 Actions 页面查看构建与部署状态。
5. 打开网站检查内容是否更新。

每一步都有容易出错的细节：

- 第 1 步：新增页面后，记得同步在 `mkdocs.yml` 的 nav 中登记，否则页面虽然能构建，但不会出现在导航栏里。
- 第 2 步：预览时重点检查页面间链接。Markdown 链接建议写相对路径，例如 `[关于](about.md)`，不要写完整的 https 地址，否则本地预览和正式站点会指向不同位置。
- 第 4 步：Actions 中构建失败时，先看日志里的第一条报错，通常是依赖版本或 YAML 缩进问题。

## 目录约定

| 路径 | 用途 | 是否提交 |
| --- | --- | --- |
| `docs/` | 网站页面源文件（Markdown） | 是 |
| `docs/` 中的图片 | 页面插图，按需新建子目录 | 是 |
| `report/` | 作业过程说明与截图 | 是 |
| `mkdocs.yml` | 站点配置与导航 | 是 |
| `requirements.txt` | 构建依赖及版本范围 | 是 |
| `site/` | 构建输出的静态网站 | 否，已在 `.gitignore` 中忽略 |

## 常用命令

在仓库根目录执行：

```bash
# 本地预览，修改文件后浏览器会自动刷新
python -m mkdocs serve

# 构建网站，--strict 会把警告当成错误，便于提前发现问题
python -m mkdocs build --strict
```

如果提示找不到 mkdocs，先安装依赖：

```bash
python -m pip install -r requirements.txt
```

## 常见问题

| 现象 | 可能原因 | 处理方式 |
| --- | --- | --- |
| 构建提示文件不存在 | nav 中写成了 `docs/index.md` | 改为 `index.md`，nav 路径相对 `docs/` |
| YAML 解析失败 | 使用了 Tab 缩进 | 统一改成空格 |
| 页面能构建但导航栏没有 | 新页面未加入 nav | 在 `mkdocs.yml` 的 nav 中登记 |
| 推送后网站没变化 | Actions 未触发或部署失败 | 到 Actions 页面查看最近一次运行 |

## 我的实践体会

本地预览和线上部署的差别，是我在这次实践中体会最深的一点。本地 `mkdocs serve` 读取的是当前工作区的文件，看起来一切正常；但线上构建使用的是仓库中已经提交的版本。如果忘记把某个文件纳入提交，就会出现“本地正常、线上缺页”的情况。所以我现在养成了习惯：提交前先用 `git status` 确认改动范围，推送后再到 Actions 确认构建结果。
