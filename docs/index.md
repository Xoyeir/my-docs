## 为什么做这个练习

平时写实验报告和课程笔记，大多是散落在本地的 Word 或 Markdown 文件，想分享给别人时要么压缩打包，要么一张张截图，内容一更新就得重新发一遍。这个练习想解决的问题很具体：让文档只有一个源文件，修改后推送到 GitHub，网站自动更新，访问地址始终不变。

## 我的实践体会

这次实践我最直观的感受是：搭建站点本身并不复杂，难的是把“修改—预览—提交—部署”这条链路跑通并保持稳定。第一次配置时，我把 nav 里的路径写成了 `docs/index.md`，构建时报找不到文件；后来才意识到 MkDocs 的导航路径是相对 `docs/` 目录解析的。这个问题我记在了[使用指南](guide.md)里，提醒自己下次不要再犯。

另一个体会是 `.gitignore` 很重要。`site/` 是每次构建都会重新生成的内容，如果误提交，仓库里会堆满 HTML 和静态资源，真正需要维护的 Markdown 反而被淹没。

## 本地预览

在仓库根目录执行以下命令，然后在浏览器打开 <http://127.0.0.1:8000>：

```bash
python -m mkdocs serve
```

更多命令和常见问题见[使用指南](guide.md)。
